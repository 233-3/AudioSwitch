## 1. 真正修改系统默认设备

Windows 没有公开的「设置默认音频端点」API。本项目使用系统内置的 `IPolicyConfig`
（CLSID `{870AF99C-171D-4F9E-AF0D-E63DF40C2BC9}`，IID `{F8679F50-850A-41CF-9C72-430F290290C8}`），
并在 `audio/policy_config.rs` 中**显式声明 vtable**，而不是依赖第三方封装：

- vtable 顺序与 Windows SDK 示例 `PolicyConfig.h` 一致：`IUnknown` 3 项 + 12 个接口方法；
- 编译期断言 vtable 大小为 15 个指针，防止漏写或重排导致偏移错位；
- 创建后立即 `QueryInterface` 校验该 IID 确实可用，失败会返回明确错误而不是「当作成功」；
- `ComGuard` 必须活到对象释放（`PolicyConfig` 持有 `_com`，字段顺序在 ptr/vtbl 之后）；
- 该接口未在文档中承诺 ABI 稳定，因此**每次切换后都会重新枚举并回读系统默认端点**，
  只有回读确认一致才判定成功并显示成功图标。

切换默认设备的唯一入口是 `audio::default_endpoint::set_default_and_verify`。

## 2. 音频角色策略

Windows 的默认端点分为 Console / Multimedia / Communications 三类。本工具：

- **同时切换** `Console` 与 `Multimedia`（常规播放使用的角色）；
- **不修改** `Communications`，避免悄悄改变会议 / 通话类应用的输出路由。

这是与用户确认过的产品决定。界面顶部会提示「切换时会同时更新系统声音与多媒体两个角色」。

## 3. 循环切换算法

规则（`audio/cycle.rs`，纯函数，无 Windows 依赖，因此可以单元测试）：

1. 严格按用户配置顺序循环，绝不按系统枚举顺序；
2. 只有「启用 + 当前 Active」的设备参与；
3. 判断依据是**实时读取的系统默认端点**，不是内存索引；
4. 当前默认设备不在列表中 → 切到第一个可用设备；
5. 当前默认设备在列表中 → 从它的下一个可用设备开始（跳过断开 / 禁用的）；
6. 只剩一个可用设备且已是默认 → 提示「无需切换」，不调用系统接口；
7. 没有任何可用设备 → 不切换，返回明确错误并显示失败图标；
8. 直接切换时目标已是默认设备 → 跳过底层调用；
9. 切换失败不更新任何「当前设备」缓存（成功状态只来自回读验证）。

## 4. 托盘事件与菜单

- 使用 Tauri 2 原生 `TrayIconBuilder`，关闭 `show_menu_on_left_click`，左键永不弹菜单；
- Windows 会分别为按下 / 抬起各派发一个 `Click` 事件，因此只处理
  `button == Left && button_state == Up`，一次物理单击只触发一次逻辑；
- 忽略 `DoubleClick`，不做鼠标位置轮询；
- 切换操作通过异步互斥锁串行化，锁被占用时新请求立即返回「正在切换中」，不排队、不并发；
- 右键菜单由系统原生弹出，与左键逻辑完全隔离。

菜单结构（顺序固定）：

```
当前输出：<真实设备名>          （禁用态，仅展示）
切换到下一个设备
──────────
已配置设备                       （分组标题）
  ✓ 设备 A                       （✓ 表示当前默认，点击直达）
    设备 B
    设备 C（不可用）              （不可用设备置灰并标注原因）
──────────
设备配置与切换顺序
打开主界面
──────────
退出
```

已配置设备直接平铺而不是放进二级菜单：循环设备通常只有 2–4 个，平铺少一次点击。
不可用设备仍然列出但置灰，避免用户误以为可以切换。

## 5. 图标状态机

- 四套真实 PNG 资源（16/20/24/32 px，按主显示器 DPI 选择尺寸），`include_bytes!` 编译进二进制；
- 图形体系：正常＝耳机（蓝）、切换中＝循环箭头（青）、成功＝对勾（绿）、失败＝感叹号（红），
  四种状态只改变底色与符号，保证在浅色 / 深色任务栏上都清晰可辨；
- 切换开始**立即**切到「切换中」图标，然后才执行系统调用；
- 成功图标在**回读验证通过之后**才显示；失败显示错误图标；
- 每个临时状态都有「代次（generation）」，延时恢复任务只在代次未被更新时才回落，
  因此连续快速切换或异常都不会把图标永久卡在成功 / 失败状态；
- tooltip 与图标状态同源生成，设备名全部来自实时枚举，tooltip 长度截断到 120 字符以内。

## 6. 设备监听

- `IMMNotificationClient` 注册设备增删、状态变化、默认设备变化、属性变化四类回调；
- 回调线程只投递事件，不做 COM 调用，避免在系统回调栈中重入；
- 300 ms 去抖窗口，把一次插拔产生的多条回调合并为一次刷新；
- 监听到默认设备变化时只同步状态，**绝不自动切换设备**；
- 注册失败时如实标记「监听降级」并启用 3 秒定时轮询兜底，界面运行状态会显示黄色「监听降级」。

## 7. 退出与单实例

- 关闭窗口 → `prevent_close` + 隐藏，托盘与监听继续工作；
- 「退出」→ 保存配置 → 注销设备通知回调并等待监听线程结束 → 移除托盘图标 → `app.exit(0)`；
- `tauri-plugin-single-instance` 保证只有一个进程，重复启动会激活已有窗口。

## 8. 开机自启

- 使用 Tauri 官方 `tauri-plugin-autostart`，写入当前用户的启动项
  （`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`），不需要管理员权限；
- 开关状态**以 `is_enabled()` 回读为准**，不在配置文件里保存副本：用户若在
  「任务管理器 → 启动」中禁用，界面会如实显示为关闭，不会出现 UI 与系统不一致；
- 设置失败（被组策略或安全软件拦截）会返回明确错误并保持界面原状；
- 卸载程序不会自动清理该启动项，卸载前处于开启状态时需在任务管理器中手动删除。

## 9. 左键默认行为

左键单击默认**打开主界面**（不切换设备）。这是按实际使用反馈做的默认值调整：
托盘误触会立刻改变正在播放的音频，代价比多点一次菜单高。需要一键切换的用户可在
「常规设置」中打开开关，行为立即生效并保存到本地。

## 10. 界面语言与主题

- 语言与主题都保存在 `config.json`（`language` / `theme`），读取时校验取值，
  非法值自动回落默认，旧版本配置（没有这两个字段）也能正常读取；
- **语言是进程级状态**：前端词表（`src/i18n.ts`）与 Rust 侧文案
  （`src-tauri/src/i18n.rs`：托盘菜单、tooltip、提示语、错误）通过同一份
  `language` 同步；切换语言后立即重绘托盘并广播快照，界面无需重启；
- 英文词表与中文词表共享同一批 key（由类型 `Record<MessageKey, string>` 保证），
  少翻一条会在 `vue-tsc` 阶段报错；
- 主题通过 `<html data-theme>` 切换 CSS 变量实现，同时调用 `window.set_theme`
  让原生标题栏跟随深浅色；CSS 里不使用 `prefers-color-scheme`，避免手动选择被系统设置覆盖；
- 切换在界面上是乐观更新：先本地生效再等后端确认，失败时回滚，
  不会出现「界面已变但配置没保存」的状态。

## 11. 线程与状态模型

- 单一事实来源在 Rust：设备列表、默认端点、监听状态都由后端维护，前端只渲染快照；
- 前端不做业务判断，状态一律来自快照与三类事件：
  `audio-state-changed`（状态变化）、`audio-switch-result`（切换结果）、`ui-navigate`（导航请求）；
- 切换流程在异步任务中串行执行：加锁 → 显示「切换中」图标 → 读实时默认端点 → 计算目标
  → `SetDefaultEndpoint` → 重新枚举回读 → 更新图标与 tooltip → 广播结果；
- 配置只在明确的用户操作后写入磁盘，运行态（图标状态、切换锁、索引缓存）一律不落盘。
